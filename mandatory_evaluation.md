# Mandatory Evaluation Commands

Run these commands from the repository root. The commands are grouped in the
order that makes the Mandatory evaluation easy to demonstrate.

## 1. Show the project and current state

```bash
pwd
git status --short
make help
```

Show the project documentation and the authoritative subject:

```bash
less README.md
less docs/AUDIT.md
less docs/DECISIONS.md
less docs/TRAINING.md
less en.subject.pdf
```

If the terminal cannot display PDF files, use:

```bash
pdftotext -layout en.subject.pdf - | less
```

## 2. Run all automated checks

```bash
make verify
```

Expected result: compilation succeeds and all tests finish with `OK`.

## 3. Show the required programs

```bash
ls -l train.py predict.py
python3 train.py --help
python3 predict.py --help
```

The two required programs are:

- `train.py`: reads the dataset, trains the model, and saves `theta0` and
  `theta1`.
- `predict.py`: prompts for a mileage, loads the persisted model, and prints
  the estimated price.

## 4. Train the model

Use the default Mandatory paths:

```bash
make train
cat model/theta.json
```

Expected result: `model/theta.json` contains exactly `theta0` and `theta1`.

Show that custom paths also work without touching the default model:

```bash
tmpdir=$(mktemp -d)
make train DATA=data.csv MODEL="$tmpdir/theta.json"
cat "$tmpdir/theta.json"
rm -rf "$tmpdir"
```

## 5. Predict with several mileages

```bash
printf '100000\n' | python3 predict.py
printf '150000\n' | python3 predict.py
printf '200000\n' | python3 predict.py
```

The program must use the public hypothesis:

```text
estimatePrice(mileage) = theta0 + theta1 * mileage
```

## 6. Demonstrate the complete flow in an isolated directory

This uses a controlled dataset and proves that prediction uses the model just
generated by training.

```bash
tmpdir=$(mktemp -d)
printf 'km,price\n100000,8000\n150000,7000\n200000,6000\n' > "$tmpdir/data.csv"
python3 train.py --data "$tmpdir/data.csv" --model "$tmpdir/theta.json"
printf '100000\n' | python3 predict.py --model "$tmpdir/theta.json"
printf '150000\n' | python3 predict.py --model "$tmpdir/theta.json"
printf '200000\n' | python3 predict.py --model "$tmpdir/theta.json"
rm -rf "$tmpdir"
```

## 7. Demonstrate validation and error handling

Invalid mileage must return an error and exit with status `1`:

```bash
printf 'not-a-number\n' | python3 predict.py; test "$?" -eq 1
printf 'nan\n' | python3 predict.py; test "$?" -eq 1
printf 'inf\n' | python3 predict.py; test "$?" -eq 1
```

Prediction must fail clearly when the model does not exist:

```bash
tmpdir=$(mktemp -d)
printf '100000\n' | python3 predict.py --model "$tmpdir/missing.json"; test "$?" -eq 1
rm -rf "$tmpdir"
```

Training must reject a missing dataset:

```bash
python3 train.py --data missing-data.csv; test "$?" -eq 1
```

## 8. Show the required formulas in the source

```bash
grep -n -A12 -B3 'def estimate_price' src/regression.py
grep -n -A38 -B3 'def gradient_descent_step' src/regression.py
grep -n -A70 -B3 'def train_model' src/regression.py
```

Point out these facts during the evaluation:

- `estimate_price` implements `theta0 + theta1 * mileage`.
- `gradient_descent_step` calculates both gradients from the old parameters.
- The function returns both updated parameters together.
- `train_model` starts from zero and applies the step repeatedly.
- Mileage standardization is internal; persisted parameters are converted back
  to the original mileage scale.
